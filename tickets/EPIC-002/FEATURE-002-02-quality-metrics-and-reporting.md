# Build Quality Metrics and Reporting System to Provide Data Quality Visibility and Alerting for DataFrame Pipelines

## Feature Summary

Data platform teams lack visibility into data quality trends across pipeline executions, making it difficult to detect gradual data degradation before it impacts downstream consumers. The Quality Metrics and Reporting system computes completeness, accuracy, and consistency metrics from quality rule results, displays them in a dedicated Spark Web UI dashboard (`Source: core/src/main/scala/org/apache/spark/ui/SparkUI.scala`), tracks trends over time via the AppStatusStore (`Source: core/src/main/scala/org/apache/spark/status/AppStatusStore.scala`), exports reports in JSON and CSV formats, and enables threshold-based alerting through the Dropwizard metrics subsystem (version 4.2.33) (`Source: core/src/main/scala/org/apache/spark/metrics/MetricsSystem.scala`) — giving teams proactive quality insight without external tooling. All quality metrics are exposed via the existing Spark REST API endpoints (`/api/v1/`), the Prometheus sink, and all configured Dropwizard metric sinks including JMX, Graphite, StatsD, Console, CSV, and Slf4j (`Source: docs/monitoring.md`).

## Dependencies

- **EPIC-002 — Declarative Data Quality Validation Framework**: Parent epic governing the overall data quality initiative, defining the scope boundaries and integration strategy for both quality rule enforcement and quality metrics reporting
- **FEATURE-002-01 — DataFrame Quality Rules Engine**: Provides the quality rule validation results (pass/fail per rule, violation counts, violation details) consumed by this feature's metric computation, dashboard rendering, trend tracking, reporting, and alerting components
- **F-002 — SQL Query Processing Engine**: Supplies the DataFrame API and Catalyst optimizer infrastructure used to compute quality metrics (aggregations, null counts, distinct counts) on validated DataFrames
- **Spark Metrics System** (`Source: core/src/main/scala/org/apache/spark/metrics/MetricsSystem.scala`): Dropwizard-based metrics framework providing MetricRegistry, Source/Sink registration, and periodic polling — used to expose quality gauges, counters, and histograms to all configured sinks
- **Spark Metrics Config** (`Source: core/src/main/scala/org/apache/spark/metrics/MetricsConfig.scala`): Configuration subsystem parsing `metrics.properties` and `spark.metrics.conf.*` Spark properties — used to configure quality-specific metric sinks and reporting intervals
- **Spark Web UI** (`Source: core/src/main/scala/org/apache/spark/ui/SparkUI.scala`): Jetty-based UI tab framework providing tab registration, page rendering, and handler mounting — used to host the quality score dashboard as a dedicated UI tab
- **Status Store** (`Source: core/src/main/scala/org/apache/spark/status/AppStatusStore.scala`): KVStore-backed data retrieval layer wrapping the persistent store — used to query historical quality metric snapshots for trend analysis and REST API responses
- **Status Listener** (`Source: core/src/main/scala/org/apache/spark/status/AppStatusListener.scala`): SparkListener event processing pipeline writing application state to the ElementTrackingStore — pattern for implementing a QualityStatusListener that captures quality metric events
- **Status Types** (`Source: core/src/main/scala/org/apache/spark/status/storeTypes.scala`): KVIndex-annotated data classes (wrapper pattern with `@KVIndex` annotations) for persisted status entities — pattern for defining `QualityMetricWrapper` and `QualityTrendWrapper` data classes
- **Element Tracking Store** (`Source: core/src/main/scala/org/apache/spark/status/ElementTrackingStore.scala`): Trigger-based element count tracking and automatic cleanup when thresholds are reached — pattern for implementing retention policy on historical quality trend data
- **Monitoring Infrastructure** (`Source: docs/monitoring.md`): REST API endpoints (`/api/v1/`), Prometheus sink, and configurable metric sinks (Console, CSV, JMX, Graphite, StatsD, Slf4j) — integration targets for quality metric exposure
- **Web UI Documentation** (`Source: docs/web-ui.md`): Existing UI tab descriptions (Jobs, Stages, Storage, Environment, Executors, SQL) — reference for quality dashboard tab design and placement

## Definition of Done

- Completeness metrics compute non-null ratio, distinct value count, and null count for each column in a validated DataFrame, returning results as a summary DataFrame with columns: `column_name`, `total_count`, `null_count`, `non_null_count`, `non_null_ratio`, `distinct_count`
- Quality score dashboard is accessible as a dedicated tab in the Spark Web UI (registered via `SparkUI.attachTab()`), displaying per-DataFrame quality scores with color-coded indicators: red for scores below the configured threshold, green for scores at or above the threshold
- Historical quality trends are persisted in the AppStatusStore (KVStore) using `QualityMetricWrapper` data classes with `@KVIndex` annotations, and are retrievable for the last N pipeline executions (configurable via `spark.quality.history.retainedRuns`, default 100), with automatic cleanup managed by ElementTrackingStore triggers
- Quality reports are exportable in both JSON and CSV formats via a programmatic API (`DataFrame.qualityReport()` method) and the REST API endpoint (`GET /api/v1/quality/reports/{dataframe_id}`)
- Alerting thresholds are configurable per rule and per DataFrame (via `spark.quality.alert.threshold.*` properties), with violations triggering Dropwizard Gauge updates exposed to all configured sinks (Prometheus, JMX, Graphite, StatsD, Console, CSV, Slf4j)
- All quality metrics are exposed via the existing Spark REST API (`/api/v1/`) under a new `/quality` resource with endpoints for current metrics, historical trends, and report generation
- Integration tests validate metric computation accuracy (null ratio calculations within 0.001 tolerance), dashboard rendering (tab presence and content verification), trend persistence (write-read round-trip for N runs), report export (JSON schema and CSV header validation), and alert triggering (threshold breach detection and gauge update verification)
- Documentation covers metrics interpretation (metric definitions and expected ranges), dashboard usage (tab navigation and drill-down), trend analysis (query API and time-range filtering), report export formats (JSON schema and CSV column definitions), and alerting configuration (`spark.quality.alert.threshold.*` property reference)
- Quality metrics computation adds no more than 5% overhead to the base quality rule validation time, measured by benchmarking metric computation on DataFrames with 1 million, 10 million, and 100 million rows
