# Implement Stream Health Monitoring to Provide Real-Time Visibility into Structured Streaming Pipeline Health

## Feature Summary

Production streaming teams lack consolidated health visibility for Structured Streaming queries; monitoring processing rates, watermark progression, state store sizes, processing lag, and checkpoint health today requires manual inspection of `StreamingQueryProgress` JSON payloads or integration with external monitoring tools, increasing mean-time-to-detection for pipeline degradation. This feature delivers a unified stream health monitoring layer that surfaces five streaming vitals — input/processing rates, watermark advancement, state store size, end-to-end processing lag, and checkpoint durability status — through the Spark Web UI Structured Streaming tab and the Dropwizard Metrics 4.2.33 sink infrastructure (Prometheus, JMX, Graphite, CSV). The implementation extends the existing `StreamingQueryProgress` reporting pipeline (`Source: sql/core/src/main/scala/org/apache/spark/sql/classic/StreamingQuery.scala`), the `StateStoreMetrics` system (`Source: sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/state/StateStore.scala` — `StateStoreMetrics`, `StateStoreCustomMetric`, `StateStoreInstanceMetric`), the Dropwizard `MetricRegistry` integration (`Source: core/src/main/scala/org/apache/spark/metrics/MetricsSystem.scala`), and the checkpoint/offset log tracking infrastructure (`Source: sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/checkpointing/OffsetSeqLog.scala`, `CommitLog.scala`).

## Dependencies

- **EPIC-005: Enhanced Real-Time Stream Observability** — Parent epic that defines the overall observability vision, encompassing both stream health monitoring (this feature) and backpressure/SLA management (FEATURE-005-02)
- **F-003 (Real-Time Stream Processing / Structured Streaming)** — Provides the streaming query execution engine, micro-batch and continuous processing modes, checkpoint semantics, watermark propagation, and the `StreamingQuery` lifecycle that this feature instruments and monitors
- **Spark Web UI — Structured Streaming Tab** — Serves as the primary display surface for stream health metrics; the existing tab already renders Input Rate, Process Rate, Input Rows, Batch Duration, Operation Duration, Global Watermark Gap, Aggregated Number Of Total State Rows, Aggregated State Memory Used In Bytes, and Aggregated Number Of State Rows Dropped By Watermark (`Source: docs/web-ui.md` — Structured Streaming section, lines 414–446)
- **StreamingQuery API** — `sql/core/src/main/scala/org/apache/spark/sql/classic/StreamingQuery.scala` exposes the `StreamingQuery` trait; `sql/core/src/main/scala/org/apache/spark/sql/classic/StreamingQueryManager.scala` manages active queries and provides `StreamingQueryProgress` reporting containing per-batch input/processing/output rates, batch durations, watermark values, and state operator metrics
- **StateStore API** — `sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/state/StateStore.scala` defines `StateStoreMetrics` (numKeys, memoryUsedBytes, customMetrics, instanceMetrics), `StateStoreCustomMetric` (sum, size, timing variants), and `StateStoreInstanceMetric` (per-partition, per-store metrics including `StateStoreSnapshotLastUploadInstanceMetric`) used to track state store health
- **Metrics System — Dropwizard 4.2.33** — `core/src/main/scala/org/apache/spark/metrics/MetricsSystem.scala` provides the `MetricRegistry`, `Source`, and `Sink` abstractions for registering streaming-specific gauges and counters; supports export to Prometheus (`PrometheusServlet`), JMX, Graphite, StatsD, CSV, and Console sinks (`Source: docs/monitoring.md` — metrics sinks section)
- **Checkpoint and Offset Tracking** — `sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/checkpointing/OffsetSeqLog.scala` tracks per-batch offset ranges; `sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/checkpointing/CommitLog.scala` records batch commit completions; both are required for computing checkpoint health and lag metrics
- **Kafka Connector** — `connector/kafka-0-10/` provides Kafka-specific consumer group offset lag tracking and per-partition offset metrics used for Kafka-aware lag detection
- **Streaming Performance Documentation** — `Source: docs/streaming/performance-tips.md` documents async progress tracking configuration and continuous processing mode behavior that influences metric collection timing and accuracy

## Definition of Done

- All 5 user stories (STORY-005-01-01 through STORY-005-01-05) are implemented, reviewed, and pass their respective acceptance criteria
- Stream processing rates (input rows/sec and processing rows/sec) are displayed in the Web UI Structured Streaming tab with per-batch numeric values and a rolling trend chart covering the last 100 batches
- Watermark progression is visualized with the current watermark timestamp, watermark advancement rate (seconds advanced per batch), and event-time gap (difference between batch timestamp and global watermark) displayed per streaming query
- State store size is monitored with per-operator metrics for number of keys and memory usage in bytes, a growth trend line over the last 100 batches, and configurable size threshold alerts that fire when state store memory exceeds a user-defined limit (configured via `spark.sql.streaming.stateStore.alertThresholdBytes`)
- Processing lag is computed as the difference between current wall-clock time and the event time of the most recently processed record, surfaced as a numeric value in the Web UI and as a named Dropwizard gauge accessible through all configured metric sinks
- Checkpoint status displays the last successful checkpoint timestamp, checkpoint write duration in milliseconds, checkpoint size in bytes, and cumulative checkpoint failure count per streaming query
- All five monitoring metrics (processing rates, watermark progression, state store size, processing lag, checkpoint status) are registered as named Dropwizard gauges and counters in the `MetricRegistry` and are accessible through all configured metric sinks — Prometheus, JMX, Graphite, StatsD, CSV, and Console — and through the REST API at `/api/v1/applications/[app-id]/streaming/statistics`
- Monitoring overhead adds less than 3% to stream processing latency at the 99th percentile when all five health monitoring capabilities are enabled, measured via a dedicated performance benchmark
- Unit tests validate metric computation accuracy for each of the five monitoring capabilities, covering both micro-batch and continuous processing modes
- Integration tests confirm end-to-end metric flow from `StreamingQueryProgress` emission through Web UI rendering and Dropwizard sink export
- Documentation covers monitoring setup instructions, metric interpretation guide (including units and expected value ranges for each metric), and Web UI navigation for all five stream health monitoring capabilities with code examples in Scala and Python
